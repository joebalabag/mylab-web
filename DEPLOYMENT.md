# MyLab Web — Deployment (Linux + nginx, Jenkins-driven)

Practical guide for deploying the built SPA to a Linux server behind nginx.
Assumes Ubuntu / Debian; commands map 1-to-1 on RHEL / Rocky (swap `apt` for
`dnf`, path prefixes are the same). Builds are driven from a **Jenkins**
workspace on the host (`/var/lib/jenkins/workspace/mylab-web`); nginx serves
the compiled `dist/` from that workspace.

Companions:
- [`GETTING_STARTED.md`](./GETTING_STARTED.md) — end-user walkthrough.
- [`DEVELOPER_SETUP.md`](./DEVELOPER_SETUP.md) — dev environment + code tour.

---

## Overview

- The frontend is a **static SPA + PWA** built by Vite. There is no Node
  process in production — nginx serves the compiled `dist/` folder.
- Environment variables are **baked into the JS bundle at build time**.
  Rebuild per environment; do not try to swap `.env` at runtime.
- Vue Router uses `createWebHistory()`, so nginx **must fall through to
  `index.html`** for deep-link URLs. `/` renders the public marketing page
  (`LandingView`); sign-in is at `/login`; the read-only public lab report
  view lives at `/lab/view?uuid=…` (opened by patients scanning a QR code).
- Backend API is called cross-origin by default. Either:
  - Point `VITE_API_BASE` at the real host and have the backend allow the
    frontend's origin via CORS, or
  - **Reverse-proxy `/api/*` through the same nginx** (recommended — same
    origin, no CORS).
- Uploads (tenant logos, doctor e-signatures, lab report headers, payment
  slips) live under `/public/uploads/*` on the backend; the SPA references
  them via `assetUrl()` in `src/api/client.js`. If your frontend and API are
  on **different** origins, you'll want to either proxy `/public/*` through
  nginx as well, or make sure `assetUrl()` produces absolute URLs.

Reference stack used in this doc:

| Piece | Value |
|---|---|
| Frontend origin | `https://mylab.edgetechph.net` |
| Backend origin  | `https://api-mylab.edgetechph.net` |
| Deploy target   | `/var/lib/jenkins/workspace/mylab-web/` (Jenkins workspace) |
| Web server      | nginx ≥ 1.18 |
| Node (for builds) | 20 LTS (on the Jenkins agent) |

Adjust hostnames / paths to match your environment.

## 1 · One-time server prep

Fresh Ubuntu 22.04 / 24.04 box:

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y nginx ufw certbot python3-certbot-nginx rsync

# Firewall — allow SSH + HTTPS. Skip if your provider handles this.
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

Node (only needed if you build **on** the same box — typically Jenkins does
this in its own agent workspace):

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

Verify nginx:

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
```

## 2 · Build the frontend

The recommended path is a **Jenkins pipeline** that clones the repo, installs
deps, builds, and (in the same job) either atomically swaps the docroot or
lets nginx read the workspace's `dist/` directly.

Manual build (on any machine with Node 20):

```bash
git clone https://github.com/joebalabag/mylab-web.git
cd mylab-web
npm ci

# Production build reads .env.production automatically
npm run build:production

# Or, for staging:
npm run build:staging
```

Output lands in `dist/`. Contents:

```
dist/
├── index.html
├── manifest.webmanifest              # PWA manifest (auto-generated by vite-plugin-pwa)
├── sw.js, workbox-*.js               # Service worker + precache
├── favicon.ico, favicon.png
├── pwa-192.png, pwa-512.png, pwa-512-maskable.png
├── og-image.png
└── assets/
    ├── index-<hash>.js
    ├── index-<hash>.css
    ├── mylab-icon-<hash>.png
    └── …
```

The `<hash>` suffixes are Vite's cache-busting fingerprint. Every deploy
gets fresh URLs, so browsers can safely cache assets for a year.

### Jenkinsfile skeleton

```groovy
pipeline {
  agent any
  environment { NODE_ENV = 'production' }
  stages {
    stage('Checkout') { steps { git url: 'https://github.com/joebalabag/mylab-web.git', branch: 'main' } }
    stage('Install')  { steps { sh 'npm ci' } }
    stage('Build')    { steps { sh 'npm run build:production' } }
    stage('Publish')  {
      steps {
        sh '''
          STAMP=$(date +%Y%m%d-%H%M%S)
          sudo mkdir -p /var/www/mylab-web/releases/$STAMP
          sudo rsync -a --delete dist/ /var/www/mylab-web/releases/$STAMP/
          sudo ln -sfn /var/www/mylab-web/releases/$STAMP /var/www/mylab-web/current
          sudo nginx -s reload
        '''
      }
    }
  }
}
```

Point nginx's `root` at `/var/www/mylab-web/current` (see §4). If you'd
rather serve directly out of the Jenkins workspace, point `root` at
`/var/lib/jenkins/workspace/mylab-web/dist` and drop the copy step — just
make sure Jenkins doesn't clean the workspace between builds.

## 3 · Upload (if you build off-box)

### Simple rsync (works everywhere)

```bash
# From your local machine:
rsync -avz --delete dist/ \
  deploy@mylab.edgetechph.net:/var/www/mylab-web/current/
```

### Atomic-swap deploys (recommended for prod)

Ship each build into its own directory and repoint a `current` symlink so
users never see a half-uploaded site:

```bash
# On the server, one-time:
sudo mkdir -p /var/www/mylab-web/releases
sudo ln -sfn /var/www/mylab-web/releases/initial /var/www/mylab-web/current

# From your local machine, per deploy:
STAMP=$(date +%Y%m%d-%H%M%S)
rsync -avz --delete dist/ \
  deploy@mylab.edgetechph.net:/var/www/mylab-web/releases/$STAMP/
ssh deploy@mylab.edgetechph.net \
  "sudo ln -sfn /var/www/mylab-web/releases/$STAMP /var/www/mylab-web/current"
```

Rollback is one SSH command: `sudo ln -sfn /var/www/mylab-web/releases/<older>
/var/www/mylab-web/current` — no rebuild required.

## 4 · nginx server block

Create `/etc/nginx/sites-available/mylab-web`:

```nginx
# ─── HTTP → HTTPS redirect ────────────────────────────────────────
server {
    listen 80;
    listen [::]:80;
    server_name mylab.edgetechph.net;

    location /.well-known/acme-challenge/ { root /var/www/html; }
    location / { return 301 https://$host$request_uri; }
}

# ─── Main site (HTTPS) ────────────────────────────────────────────
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name mylab.edgetechph.net;

    root  /var/www/mylab-web/current;        # or /var/lib/jenkins/workspace/mylab-web/dist
    index index.html;

    # Filled in by certbot on first run.
    ssl_certificate     /etc/letsencrypt/live/mylab.edgetechph.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mylab.edgetechph.net/privkey.pem;
    include             /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam         /etc/letsencrypt/ssl-dhparams.pem;

    # ── Security headers ──────────────────────────────────────────
    add_header X-Frame-Options           "SAMEORIGIN" always;
    add_header X-Content-Type-Options    "nosniff"    always;
    add_header Referrer-Policy           "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy        "camera=(), microphone=(), geolocation=()" always;

    # ── Gzip ──────────────────────────────────────────────────────
    gzip              on;
    gzip_vary         on;
    gzip_min_length   1024;
    gzip_comp_level   6;
    gzip_types        text/plain text/css text/xml application/json
                      application/javascript application/xml+rss
                      application/atom+xml image/svg+xml
                      application/manifest+json;

    # ── Static assets — long cache (hashed filenames) ─────────────
    location ~* \.(js|css|png|jpg|jpeg|gif|webp|svg|ico|woff2?|ttf|eot)$ {
        access_log off;
        expires    1y;
        add_header Cache-Control "public, immutable";
        try_files  $uri =404;
    }

    # ── PWA — never cache the service worker or manifest ──────────
    location = /sw.js               { add_header Cache-Control "no-store"; try_files $uri =404; }
    location = /manifest.webmanifest{ add_header Cache-Control "no-store"; try_files $uri =404; }

    # ── Reverse-proxy the API to avoid CORS ───────────────────────
    # If you'd rather keep the backend on api-mylab.edgetechph.net and deal
    # with CORS on the backend, delete this block AND set
    # VITE_API_BASE=https://api-mylab.edgetechph.net/api in .env.production.
    location /api/ {
        proxy_pass          https://api-mylab.edgetechph.net/api/;
        proxy_http_version  1.1;
        proxy_set_header    Host              api-mylab.edgetechph.net;
        proxy_set_header    X-Real-IP         $remote_addr;
        proxy_set_header    X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header    X-Forwarded-Proto https;
        proxy_ssl_server_name on;

        # Upload limit — payment-slip and doctor-signature images, plus the
        # base64-encoded PDF the frontend posts to /api/lab-report/:uuid/email-result
        # after Tag as Final. Must be ≥ the backend's Nest body-parser limit (20mb).
        client_max_body_size 20m;
        proxy_read_timeout   60s;
    }

    # ── Serve /public/uploads/* if the frontend needs cross-origin uploads ──
    # Not required when you reverse-proxy /api above (relative /public URLs
    # will resolve to the same origin). Uncomment when the backend runs on a
    # separate host and you want tenant logos / lab-report headers / doctor
    # signatures served through this domain.
    # location /public/ {
    #     proxy_pass https://api-mylab.edgetechph.net/public/;
    # }

    # ── SPA fallback — HTML5 history mode ─────────────────────────
    # Every unmatched URL falls through to index.html so Vue Router can
    # handle it. Do NOT cache index.html.
    location / {
        try_files $uri $uri/ /index.html;
    }

    location = /index.html {
        add_header Cache-Control "no-store, no-cache, must-revalidate";
        expires    -1;
    }
}
```

Enable the site:

```bash
sudo ln -sfn /etc/nginx/sites-available/mylab-web \
             /etc/nginx/sites-enabled/mylab-web
sudo nginx -t
sudo systemctl reload nginx
```

### If you reverse-proxied `/api/` above

Set the frontend to use a **relative** API base so it hits your own domain:

```env
# .env.production
VITE_API_BASE=/api
```

Rebuild → deploy. No CORS to configure.

### If you did **not** reverse-proxy

Keep the direct URL:

```env
VITE_API_BASE=https://api-mylab.edgetechph.net/api
```

And make sure the backend's `CORS_ORIGINS` env includes
`https://mylab.edgetechph.net`. See the API deployment guide for details.

## 5 · SSL certificate

Certbot handles the initial cert issue **and** the nginx snippet edits:

```bash
sudo certbot --nginx -d mylab.edgetechph.net
```

- Answer the two prompts: email address, agree to ToS.
- Certbot re-writes the two `ssl_*` lines in your server block to point at
  Let's Encrypt paths — you no longer need the placeholder values above.

Renewal is automatic (systemd timer installed by the certbot package):

```bash
sudo systemctl list-timers | grep certbot
sudo certbot renew --dry-run   # sanity check
```

## 6 · Deploy checklist per release

Jenkins pipeline handles this automatically; manual equivalent:

```bash
# On the build machine (or Jenkins agent)
git pull
npm ci
npm run build:production
STAMP=$(date +%Y%m%d-%H%M%S)
rsync -avz --delete dist/ \
  deploy@mylab.edgetechph.net:/var/www/mylab-web/releases/$STAMP/

# On the server
ssh deploy@mylab.edgetechph.net "\
  sudo ln -sfn /var/www/mylab-web/releases/$STAMP /var/www/mylab-web/current && \
  sudo nginx -s reload"
```

Smoke tests after deploy:

- Hit `https://mylab.edgetechph.net/` in an incognito window — the public
  landing page should render (no auth prompt).
- Click **Sign in** (or hit `/login` directly) and sign in with a known
  tenant account.
- Land on `/home` (`WelcomeView`). Confirm the sidebar shows only the
  modules the account has access to.
- Open **Patients**, **Patient Cases**, **Cashier**, and **Laboratory** to
  confirm each view loads.
- Open a public lab-report link (`/lab/view?uuid=…&t=…`) in an incognito
  window and confirm the read-only report renders.
- If you reverse-proxied `/api/`, verify a POST works (e.g. save a minor
  Company Settings change or create a discount).
- Install as a PWA: browser install prompt should appear (Chrome/Edge on
  desktop, Add-to-Home-Screen on mobile). Installed app should open at
  `/login` in standalone mode.

## 7 · Rollback

```bash
ssh deploy@mylab.edgetechph.net
ls -1 /var/www/mylab-web/releases       # find the previous stamp
sudo ln -sfn /var/www/mylab-web/releases/<older-stamp> \
             /var/www/mylab-web/current
sudo nginx -s reload
```

No rebuild required. Back to good state in ~5 seconds.

Prune old releases occasionally to keep disk usage sane:

```bash
cd /var/www/mylab-web/releases
sudo ls -1t | tail -n +11 | xargs -r sudo rm -rf   # keep newest 10
```

## 8 · Optional: GitHub Actions deploy

Skeleton `.github/workflows/deploy.yml` (mirrors the Jenkinsfile shape):

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - run: npm ci
      - run: npm run build:production

      - name: Rsync to server
        uses: burnett01/rsync-deployments@6.0.0
        with:
          switches: -avz --delete
          path: dist/
          remote_path: /var/www/mylab-web/releases/${{ github.sha }}/
          remote_host: ${{ secrets.DEPLOY_HOST }}
          remote_user: ${{ secrets.DEPLOY_USER }}
          remote_key: ${{ secrets.DEPLOY_KEY }}

      - name: Swap symlink
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_KEY }}
          script: |
            sudo ln -sfn /var/www/mylab-web/releases/${{ github.sha }} \
                         /var/www/mylab-web/current
            sudo nginx -s reload
```

Set repo secrets `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KEY` in
**Settings → Secrets and variables → Actions**.

## 9 · Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Deep link like `/patients` shows a **404 from nginx** | `try_files … /index.html;` missing on the `location /` block. |
| `Content-Type: application/octet-stream` on `.js` files | nginx MIME types not loaded. Ensure `include /etc/nginx/mime.types;` is in `nginx.conf`. |
| Blank page, console shows CORS blocked | You did **not** reverse-proxy `/api/` **and** the backend `CORS_ORIGINS` doesn't include this frontend origin. Either enable the proxy block (recommended) or add `https://mylab.edgetechph.net` to the API's `CORS_ORIGINS`. |
| API calls hit the wrong host after a build | You edited `.env.production` but didn't rebuild. `VITE_*` vars are baked in — rebuild. |
| Logo / tenant image 404 in production but works locally | You're pointing directly at the backend host for images. Either serve `/public/` through the proxy (see commented block above) or make sure `assetUrl()` (`src/api/client.js`) is prefixing with the API origin. |
| Cache never busts | Client is caching `index.html`. Verify the `location = /index.html` block sets `Cache-Control: no-store`. |
| PWA won't update on installed devices | Service worker cached itself. Ensure `location = /sw.js` sets `Cache-Control: no-store`. The vite-plugin-pwa registration uses `autoUpdate`, so a fresh SW should take over within a page load or two after deploy. |
| Install prompt never appears | Chrome / Edge only show the install prompt on **HTTPS** origins (except localhost). Verify the site is HTTPS and the manifest link + icons are reachable at `/manifest.webmanifest`, `/pwa-192.png`, `/pwa-512.png`. |
| `413 Request Entity Too Large` on payment / signature upload or emailing a finalized lab report | `client_max_body_size` too low on the `/api/` proxy block. Bump to `20m` (matches the backend's Nest body-parser limit set in `main.ts`). |
| Certbot renew warns "another instance running" | Old `certbot` cron ran alongside the systemd timer. Disable the crontab entry or the timer — pick one. |
| Public lab-report link (`/lab/view?…`) shows the login form | The catch-all in `router/index.js` is wrong, OR nginx didn't fall through to `index.html`. Confirm the URL isn't rewritten. |

## 10 · Hardening later

Non-blocking, but worth doing before public launch:

- **CSP header** — draft a Content-Security-Policy once you know every
  origin the app talks to (PayPal SDK, Google Fonts, error reporting, etc).
- **fail2ban** on SSH.
- **Log rotation** — nginx defaults are fine on Ubuntu; verify with
  `logrotate -d /etc/logrotate.d/nginx`.
- **Monitoring** — a lightweight uptime check hitting `/index.html` +
  something more thoughtful (e.g. Sentry / GlitchTip for JS errors).
- **HTTP/3** — nginx 1.25+ supports QUIC. Not required, but nice.
